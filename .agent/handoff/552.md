## Summary

Implemented the core production change for the Context-Window Handoff fix. `step_limits.admit_request` now takes an optional per-request `output_cap` override; `run_model_request` threads an `output_cap` override through admission, invoke (`max_tokens`), and retries, and its docstring documents the handoff use. `AgentStepDeps` gained `handoff_token_cap`, and `HandoffProducer` was redefined (placed after `AgentStepDeps`) as `Callable[[AgentStepDeps, ExecutionTally, WorkflowStep, int, list[BaseMessage], PinWitness], ContinuationSnapshot | AgentStepOutcome]` — the producer settles spend itself. `agent_handoff.py` was rewritten: new `build_handoff_instruction` (conversation + instruction, identifiers only) and `produce_handoff_snapshot` (overflow check `estimate + cap > threshold` raises `HandoffFailure` before any send; admitted turn via `run_model_request` with `record_main_context=False`, `output_cap=cap`, model forked under `handoff_turn_conversation` with `bind_tools([])`; admission refusal maps to `tally.limit`, deadline to `tally.deadline`; response parsed via `parse_snapshot_response`). `perform_handoff` takes a new `witness` param (loop call updated), returns producer outcomes directly, removed the fabricated `len(snapshot)/4` spend and after-spend check, re-raises `PinViolation`, keeps count/size/persist/ledger-event/fresh-opening logic plus a flush after `reset_main_context`. Deleted dead `build_handoff_prompt` and `execute_handoff_turn` from `context_handoff.py` (plus now-unused `TokenPrices` import). `tests/support/agent_step_deps.py` accepts `handoff_token_cap`. None of this is committed; `git status` shows all six files modified, no commits on the branch.
