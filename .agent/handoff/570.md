## Design notes / pitfalls
- Durable halt fact = `Execution Summary["provider_failure"]` marker in the
  `step_executions` row (no schema change); poll loop reads ledger, so it
  works live and after restart. Sub-agent failures write no such marker →
  never count by themselves (§9.8).
- `request_model_response` catches `ModelError` but NOT `PinViolation`
  (unrelated `Exception` subclass) — gateway fail-closed path preserved.
- `perform_handoff` producer path unchanged: `run_model_request` raising
  `ModelError` there still becomes `handoff_failed` (§9.9) via its
  `except Exception`.
- `_run_spawn_group` has a pre-existing duplicate-`outcomes.append` quirk
  (extra entries ignored by caller's `zip`); left alone, out of scope.
- `AgentStepOutcome.detail` is dropped by `ProductionStepExecutor`
  (StepOutcome has no detail) — the durable record is the summary marker;
  `run_agent_step`-level tests should assert `outcome.detail`.
- Env note: run pytest/mypy with the `env -u …` prefix; container has no
  Docker/PHP/Composer — skip those scripts and say so in final summary.
