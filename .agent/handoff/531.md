## Summary

Pure refactor (part of #487, slice 2 of 4): one pin witness per conversation.

- New file `src/coding_agent/provider/pin_witness.py`: `PinWitness` built from
  (`record_event`, `attempt_id`, `pin`, `step_id`, `seq`, optional `call_id`) —
  never from `AgentStepDeps`. Owns response numbering and event labels
  ("model response N in step#seq" / "… of sub-agent 'x'"). Methods:
  `record_success(response) -> observed`, `violation_from_response(response) ->
  PinViolation`, `violation_from_error(exc) -> PinViolation`; caller writes
  `raise witness.…(…)`, gateway path chains `from exc`. Only calls the verdict
  functions (`check_direct_pin`, `check_reported_effort`,
  `check_gateway_error_exc`); holds no identity rules. `_gateway_ledger_fragment`
  and `_pin_violation_payload` moved here as internals (same payloads/labels).
  `record_event` is `ExecutionTally.record_event` in production (appends to
  tally events AND records to Run Ledger), a fake collector in tests — this
  keeps `outcome.events` and ledger kinds/payloads/order unchanged.
- `src/coding_agent/runtime/graph/agent_step.py`: step loop and
  `_run_default_subagent` now record `model_response`/`pin_violation` only
  through a `PinWitness`; all six payload-building copies and all
  `PinViolation(...)` constructions removed; helpers
  `_gateway_ledger_fragment`/`_pin_violation_payload`/`_effort_check_of`
  deleted. Ordering preserved: step loop settles spend before recording and
  records success only after the limit check; sub-agent records first, spawn
  group settles from the carried response. Callers still call verdict
  functions for branch decisions (pure, no side effects); the witness
  re-calls them to build payloads/exceptions.
- New file `tests/test_pin_witness.py`: 6 tests with fake responses/recorder
  and direct + gateway pins (success numbering, identity violation, effort
  violation, gateway-error violation, sub-agent `call_id` labelling, gateway
  success). No existing test file edited.
