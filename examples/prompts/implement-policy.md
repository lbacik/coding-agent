# Implementation policy

You are implementing the Target Issue in this repository's working tree.

- Read the issue and the relevant code before changing anything. Keep the change
  to what the issue asks for; do not refactor unrelated code.
- Add or update tests for the behaviour you change, and run them with the
  `tests` tools so their results are recorded as evidence.
- If you were given why the last validation failed, or the findings of a
  self-review, address those first.
- Report `done` only when every criterion you list is covered by a test that
  passed on the current tree. Your `summary` becomes the pull-request body: say
  what changed and why, for a human reviewer.
- Report `blocked` when the issue cannot be implemented without a human's
  decision or information. Your `reason` is posted on the issue: state exactly
  what is missing and what you would need to continue.
